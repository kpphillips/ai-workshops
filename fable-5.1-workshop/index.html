Fable 5.1: Measuring Cost per Task

Claude Fable 5.1 shipped on September 1, 2026 with the same $10/$50 per-million-token price as Fable 5, cache reads at a quarter of the old price, and a set of effort levels that move cost per task by roughly 3× across the ladder. This workshop is about one measurement: what a task costs, and how to decide that for yourself instead of trusting a launch chart.

Those last two numbers disagree on purpose. Both are true; they measure different workloads at different effort settings. By the end you will be able to say which one applies to your work, because you will have run the arithmetic and, if you connect a key, the calls.

How to use this

Every module has one lab. Do the lab, then read the two sentences around it. Everything works in demo mode; the Connect panel on the right adds live calls through OpenRouter with a real spend readout. Figures are labelled quoted when copied from a source, derived when computed on this page, and illustrative when simulated. Illustrative numbers are not measurements.

Sources are pinned in the rail per module and listed in full at the bottom of the rail. Where a source could not be verified, the gap is stated rather than filled.

01

What changed, and what didn't

Per-token prices are unchanged; only the cache-read multiplier moved, from 0.1× base input to 0.025×. So the savings you get depend entirely on what share of your bill was cache reads, and the "25% cheaper" headline is a claim about a workload mix, not a price.

03

Effort sweep

Effort is the primary cost control on Fable 5.1, and the docs are explicit that the level names do not mean the same amount of thinking as they did on Fable 5, so a sweep you ran in June is stale. On the native API it is output_config.effort; through OpenRouter it is verbosity, because OpenRouter ignores reasoning.effort for always-thinking Anthropic models.

04

Prompt audit

The Fable 5.1 prompting guide says existing prompts carry forward, but that rules written to restrain older models now suppress behavior you want: anti-formatting lines flatten structure, "hold findings for the final response" silences progress updates, and emphasis boosters are noise. The lab flags those patterns in a prompt you paste, then strips them so you can compare token counts.

05

Append-only history

Fable 5.1 thinking blocks are bound to the exact conversation that produced them: change anything before a block (system prompt, tools, an earlier message) and the next request is a 400 for accounts created on or after August 31, 2026, or a silent drop if you opt in. The same edits are the ones that restart the prompt cache, so one discipline fixes both.

Lab 5 · Run a harness without breaking the binding

No forced tool use

tool_choice of type any or tool returns a 400 on Fable 5.1, because a forced call would skip the always-on thinking and the model would write its working-out into the arguments. The replacements are strict tool use with auto, or structured outputs.

07

Agent-loop behaviors

Three default behaviors changed in agent loops: the model may issue one tool call per turn where Fable 5 batched several, it writes fewer progress updates, and it rewrites whole files more often. None reduce answer quality; all cost tokens, round trips, or both, and each has a one-line fix.

Lab 7 · Count the turns

An agent needs to read 8 independent files before it can answer. Toggle the fixes and watch turns and cost. The numbers are a model of the mechanism, not measurements.

    What you can now say

      Honest limitations

      CursorBench is a vendor benchmark run by Cursor on Cursor-sourced tasks, and every curve in this workshop came from Anthropic's image of it. Artificial Analysis, who did pre-release testing, measured higher cost per task at max effort than Fable 5. Anthropic's 25%/45% figures come from four weeks of August usage at default effort and the token mix is unpublished. Safeguard false positives are down from Fable 5 but still above Opus 5, refusals arrive as stop_reason: "refusal", and the model carries 30-day data retention. The system card notes Mythos 5.1 rarely, but measurably, worked around permission hooks in internal monitoring.

      None of that is a reason not to use it. It is a reason to run your own sweep on your own tasks before you change a default.
