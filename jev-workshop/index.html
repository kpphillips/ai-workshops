    Architecting with System One AI

    Building zero-hallucination workflows with Jev, TypeSafe's typed decision model, and the one thing "zero hallucination" doesn't actually promise.

    Jev launched in early access on September 15, 2026, from TypeSafe AI (founded by Diogo Almeida, a co-author of the InstructGPT work behind ChatGPT). Every figure in this workshop is labeled by source, whether vendor-published, independently reported, or derived here, because a three-day-old platform is exactly where that discipline matters most.

    01: Paradigm shift

    Some problems need a paragraph. Some need a checkbox.

    Chat models are built to produce text for a person to read. A lot of what production code actually asks an LLM for isn't text at all: it's a decision the next line of code branches on. Jev is built only for the second kind.

    TakeawayIf your code does JSON.parse() on the model's answer, you didn't need a writer. You needed a decision.

    02: Sampling

    One token at a time, versus all at once

    An LLM writes an answer the way you'd write a sentence: word by word, each one conditioned on the last. Jev's parallel sampler answers every question in the same pass, so there's no sequence to wait on.

    TakeawayAdding a 4th question to a Jev call barely moves the latency. Adding a 4th field to a JSON prompt makes the LLM write more tokens, one at a time.

    03: Primitives

    Three question types, one flagship: the Interrupt Router

    Every Jev call is a state plus a map of typed questions. There are exactly three question shapes: Choice (pick an option), Score (rate against a rubric), Noul (a calibrated yes/no). This is the schema we'll build on for the rest of the workshop: a real-time engine that decides, for every incoming signal (a Slack DM, an alert, a text), whether it should interrupt you right now, wait for your next check-in, or never surface at all.

    TakeawayDecompose the judgment into atomic questions in the schema. Combine and weight the results in your own code, not in a prompt.

    04: Calibration

    RLCD: training the number to mean what it says

    Ask a chat model for a confidence score and you usually get an overconfident, inconsistent guess, because it was never trained to make that number track reality. RLCD (Reinforcement Learning for Calibrated Decisions) trains Jev specifically so that stated confidence tracks actual accuracy: 70% confidence should be right about 70% of the time.

    05: The gap

    "Zero hallucination" means zero malformed answers, not zero wrong ones

    TypeSafe's own launch post says it directly: the 0% figure "is not empirical. Schema matching is guaranteed." Jev cannot return a value outside your schema. It can still confidently pick the wrong value in your schema, because it only knows what's in the state you sent it.

    TakeawaySchema-valid and correct are two different guarantees. Jev gives you the first one automatically. The second one is still your job, through better state, thresholds, and review.

    06: The refactor

    Hands-on: replacing json_mode with a typed call

    Same job, two implementations. The Old Way asks an LLM to write JSON, then parses, validates, and retries when it doesn't match. The Jev Way asks a typed question and gets a typed answer back, with no third step.

    Code: the old way

    LLM call + schema validation + retry loop

    const TicketSchema = z.object({ action: z.enum(["interrupt_now","batch","suppress"]), urgency: z.number().min(0).max(3), needs_human_eventually: z.boolean(), }); async function routeSignal(state, attempt = 1) { const raw = await callOpenRouter({ model: "anthropic/claude-haiku-4.5", prompt: buildJsonModePrompt(state), }); try { return TicketSchema.parse(JSON.parse(stripFences(raw))); } catch (e) { if (attempt >= 3) throw e; return routeSignal(state, attempt + 1); // burns another full generation } }

    07: Escalation

    What to do when confidence is low: gate it, don't guess

    Confidence isn't just a number to log. It's a routing decision. Set a threshold: above it, act automatically; below it, hand it to a person.

    The tradeoffLower the threshold and more gets auto-resolved, including more of the calls that were actually wrong. There's no free lunch here, only where you want the line.

    08: Go deeper, on-call routing

    High-cardinality choice: 32 teams, one alert

    Jev supports Choice cardinality up to 255. Past a certain width, TypeSafe's own approach is a two-stage pattern: score every candidate independently, then make an explicit choice among the top few, rather than one 32-way vote in a single pass.
