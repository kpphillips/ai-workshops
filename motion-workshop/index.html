Directing motion as code with Opus 5.5

A model can write code that animates text, charts and shapes. Whether the result feels directed or generic depends on what you hand it: beats in seconds, durations, easing curves, springs, stagger. You will write a motion brief, retime a scene, tune the numbers, have a model generate an animation, check its frames, revise it, and carry the same package to Claude Motion if you have it.

Quoted published by the linked source Derived computed on this page Illustrative hand-authored demo, not measurements Your run a live call you paid for Convention this workshop's choice, not a spec Community a third-party claim, untested here

Every module is a lab: you do one thing, read a result, move on. Nothing here asks you for answers or gives you a mark. Animations play on this page, inside a sandbox, and nothing starts by itself except the line above. Labs run in demo mode with hand-authored animations, labelled illustrative, until you connect an OpenRouter key in the Live labs panel (right rail; at the bottom on phones). Demo mode teaches every lab. Live mode makes the output yours.

What Claude Motion is, per Anthropic

Quoted

Claude Motion is the in-app endpoint of this workflow, not the subject of the workshop. Everything below comes from two Anthropic pages: the Get started with Claude Motion help article and the Dashboards and Motion announcement (October 8, 2026).

“Claude Motion is available in beta on Team and Enterprise plans.”Help center. It is on by default on Team plans; on Enterprise, off until an owner turns it on in Organization settings > Artifacts.
“An animation is an artifact made from the Motion template. Claude builds it from your prompt as code that animates the text, charts, shapes, and images in it, and it plays like a short video.”Help center, How Claude Motion works
“Claude Motion doesn't use a video generation model, so it doesn't create realistic footage or people.”Help center, How Claude Motion works
“To download an animation, click "Export" and choose MP4.”Help center, Export and share
What Anthropic's pages do not say Neither page states which model Claude Motion uses, and neither states its code stack (for example HTML, SVG, canvas or a video library). Neither mentions an API for Motion. So this workshop calls a model through OpenRouter and previews the code itself. What you build here is the same idea, animation as code, not a copy of Motion.
Community sources Community Two third-party sources inspired the method. An X article by @flxrnc, “Opus 5.5 Motion Lab”, argues that directed prompts with numbers beat vague ones and that a model can check its own frames. The GitHub repo whaleyxbt/claude-motion (third party, MIT license, no relation to the Claude product) is an agent toolkit built around the same ideas. Neither is Anthropic's. Any claim they make about what Opus 5.5 can do with motion is a community claim and is not tested here; the labs let you test it yourself.

The contract every model-written animation must meet

Convention

Model output is untrusted code. This page runs it only inside an <iframe sandbox="allow-scripts" srcdoc> with no allow-same-origin, so the code gets no access to this page, its storage, or your key. A Content-Security-Policy injected into the document blocks the network as a second wall. Before any frame plays, the page checks the document against this contract and shows an error if it breaks a rule.

RuleValue
One HTML document, inline CSS and JS onlyno src, link, import or @import
Stage element #stage (div, svg or canvas)640 x 360 px, fixed
window.DURATION1 to 12 s, fixed
window.renderAt(t), t in secondspure function of t, any order
Frame rate for stepping and sheets30 fps (frame n = n / 30 s)
No network, no libraries, no clocks, no randomnessCSP plus static checks
Code size20,000 characters max
Output tokens per replycapped in Live labs (default 6,000)

The page owns time: it calls renderAt(t) by message. That is why a scrubber, frame stepping and contact sheets work on any stack. A runaway loop in model code can still freeze a tab; the static check rejects the obvious forms, and reloading the page clears the rest.

1. Vague versus directed

Same idea, two prompts. The idea: a six-second explainer that shows weekly signups rising to 18%. The vague prompt names no timing, so everything happens together and evenly. The directed prompt gives beats, curves, a spring and a stagger. Play both on one clock, then step frame by frame and watch when each element starts.

3. Edit the beats on a timeline

  
A beat is a named moment with a start time. At 30 fps every start snaps to a frame, so "1.00 s" and "frame 30" are the same fact. Drag a bar, or focus it and use the arrow keys (shift for five frames). The second scene below retimes live; the first keeps the starting beats so you can compare.

4. Easing and springs are numbers

  
"Smooth" is not an instruction. A cubic-bezier is four numbers and a duration. A spring is a stiffness and a damping. Tune one, watch a dot and a card move, read the measured values, and put the numbers in your prompt so the model does not have to guess.

6. The frame-check loop

  
A model cannot watch a video, but you can show it frames. Render a contact sheet, find the frame where the motion goes wrong, and write a note tied to that frame number: "frame 84 peaks late", not "make it snappier". The model revises, and you compare the same frames before and after. A community repo describes the same loop, and suggests higher effort for the review step Community; that suggestion is not tested here, but the effort control in Live labs lets you try it.
