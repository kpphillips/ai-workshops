WHAT IS OPUS 4.8 — AND WHEN TO USE IT

A plain-language briefing before you touch the labs. Read this even if you just want the gist.

Claude Opus 4.8 (released May 28, 2026) is Anthropic's most capable generally-available model. It's built for the hard stuff: complex reasoning, long-running agentic coding, and high-autonomy work where getting it right matters more than getting it cheap. Same price as Opus 4.7 — $5 per million input tokens, $25 per million output — but with noticeably better judgment and honesty.

The headline of this release isn't a bigger context window or a price cut. It's control: a dial that lets you decide how hard the model thinks, so you stop overpaying for simple questions and underthinking on hard ones.

// WHAT'S ACTUALLY NEW

EFFORT CONTROL

A dial — low → medium → high → xhigh → max — that sets how many tokens Claude spends thinking and responding. Now also a slider in claude.ai next to the model picker, for everyone. This is the lever that saves you money.

API: output_config.effort

ADAPTIVE THINKING

The model decides per-turn whether it needs to reason at all. Quick lookups answer instantly; multi-step problems get deliberate reasoning first. Fewer wasted "thinking" tokens than 4.7 at the same effort.

thinking: adaptive

HIGHER HONESTY

Roughly 4× less likely than 4.7 to let a flaw in code pass unflagged, and more willing to say "I'm not sure" instead of confidently bluffing. On long tasks, that prevents small errors from compounding.

Measured on alignment evals

FAST MODE & DYNAMIC WORKFLOWS

Fast mode (research preview) runs the same model ~2.5× faster at premium price. Dynamic Workflows (Claude Code, research preview) lets Claude plan and spawn many parallel sub-agents for codebase-scale jobs — and shows a cost confirmation before it runs.

// WHICH MODEL SHOULD YOU ACTUALLY USE?

The biggest cost mistake is running everything on the most powerful model. Match the model to the job:

◆

Opus 4.8 — the heavyweight

Use it for the genuinely hard things: complex architecture, multi-step debugging, long agentic coding runs, deep research, and anything where a wrong answer is expensive. It's the most capable — and the priciest per token.
$5 / $25 per M tokens · claude-opus-4-8
◈

Sonnet 4.6 — the everyday workhorse

About 40% cheaper than Opus and the right default for most day-to-day work: routine coding, code review, writing, summaries, classification, and tool use. Reach for this first; escalate to Opus only when Sonnet visibly struggles.
~$3 / $15 per M tokens · claude-sonnet-4-6
⚡

Haiku 4.5 — the sprinter

Fastest and cheapest. Perfect for quick questions, formatting, simple extraction, and high-volume tasks where speed and cost beat depth. Throwaway questions live here.
~$1 / $5 per M tokens · claude-haiku-4-5
The everyday rule of thumb: Default to Sonnet at high effort. Drop to Haiku + low effort for quick/simple stuff. Jump to Opus + xhigh/max only for the hard, high-stakes work. You'll get the same quality on what matters and spend a fraction of what "always Opus" costs.

  • Don't host it publicly with your key. This is a local prototyping tool, not a public website where others could rack up charges on your key.

TL;DR — safe to run locally with your own (ideally limited/rotatable) key. Read the source if you didn't get it from someone you trust. Revoke the key when you're done if you're cautious.

shown  = (≈prompt÷4) × $5/M  +  max_tokens × $25/M   ← worst case
  • The estimate is a ceiling, not a prediction. It assumes the model uses your full token cap. Most runs use less, so your actual cost is usually lower — that's why it says "most runs cost less."
  • Reasoning tokens are included. Thinking tokens are billed as output tokens at the normal $25/M rate (no separate "reasoning" price), and they're already inside usage.output_tokens — so both the estimate and the actual figure cover them. You pay for the full thinking even though the API only returns a summary of it.
  • Higher effort = more thinking = higher cost. Same prompt at max can use several times the tokens of low. The amount of thinking also varies run-to-run, so the same prompt won't cost exactly the same twice.

CLAUDE CODE & DYNAMIC WORKFLOWS

Everything so far was a single API call you ran in this page. The next step up — having Claude plan and run an army of sub-agents — lives in Claude Code, not the raw API. Here's what it is and exactly how to try it yourself.

THIS WORKSHOP

THE API

You send one request and get one response. You control every call, every token, every model choice. Perfect for building features into your own apps. That's every lab in tabs 02–06.

THE NEXT TIER

CLAUDE CODE

An agentic coding tool that runs in your terminal, desktop app, or IDE. It can read your files, run commands, and — with Dynamic Workflows — plan a big job and execute it across many sub-agents on its own.

// WHAT ARE DYNAMIC WORKFLOWS?

For jobs too big for one pass — a bug hunt across a whole service, a migration touching hundreds of files, a plan you want stress-tested from every angle — Claude writes an orchestration script on the fly and fans the work out across tens to hundreds of parallel sub-agents in a single session, checking its own work before anything reaches you. Independent agents attack the problem from different angles; other agents try to refute their findings; the run iterates until answers converge.

It's a research preview in the Claude Code CLI, Desktop, and VS Code extension (Max, Team, and Enterprise plans). The famous example: a developer used it to port Bun from Zig to Rust — ~750k lines, 99.8% of the test suite passing — with hundreds of agents working in parallel.

⚠ Why you can't run this from this page: Dynamic Workflows needs the Claude Code runtime to write and execute its orchestration script — a single browser API call can't spawn sub-agents. So instead of faking it, the steps below are real commands you run in your own terminal. And heads up: a workflow can consume far more tokens than a normal session (a 10k-token chat task can become 100k+), so start scoped.
// WALKTHROUGH — TRY IT YOURSELF
  1. Install Claude Code (Node 18+). One time:
    npm install -g @anthropic-ai/claude-code
  2. Open it in a real project folder — a repo with actual code to work on:
    cd ~/code/your-project claude
  3. Make sure you're on Opus 4.8, then turn on auto mode so the sub-agents don't stop on every prompt. Inside the Claude Code session:
    /model opus # use Opus 4.8 /effort xhigh # recommended for agentic work
  4. Kick off a workflow. Just use the word "workflow" in your prompt — Claude plans it and asks you to confirm before running. Try this (edit the scope to match your repo):
    Create a workflow to audit this codebase for security issues: hard-coded secrets, missing input validation, and unsafe SQL. Have independent agents verify each finding before reporting, and give me a severity-ranked summary. Scope it to the /src folder.
  5. Read the confirmation card, then approve. On first launch Claude Code shows the workflow name, the planned phases, the number of agents, and a token-usage caution — with Once, Always, and Deny. Pick "View raw script" if you want to read the exact JavaScript it'll run. This card is your cost safety valve — read it.
  6. Watch it run. Progress shows in the Background tasks pane (Desktop) or inline (CLI). Sub-agents run in parallel; the run saves progress so an interruption resumes instead of restarting.
Shortcut — ultracode: instead of asking for a workflow each time, switch on the Claude Code ultracode setting in the effort menu. It sets effort to xhigh and lets Claude decide on its own when a task is big enough to warrant a workflow.
// HOW THE COST STACKS UP
DYNAMIC WORKFLOW  — Claude Code, not this workshop
orchestrator (writes the script)
   ├─ sub-agent 1   (own input + thinking + output)
   ├─ sub-agent 2
   ├─ …  tens–hundreds, cap ~1,000
   └─ verifier agents  re-checking the above
total ≈ Σ every agent's (input + thinking + output)
  • Each agent pays its own context overhead, so total cost can be an order of magnitude above a normal session. The token math is the same per agent as the single-call diagram in the Long-Horizon lab — just multiplied across the fleet.
  • How many agents ran? Before: the confirmation card shows planned agent counts. During: the progress pane. After: clean per-sub-agent token breakdowns aren't fully surfaced yet — you mostly see aggregate session usage, so start scoped to calibrate.
  • Guardrails: org admins can disable workflows entirely; the first-run confirmation is on by default; and you can set token budgets before a big run.
▸ ▶ SEE THE PYTHON — DIY PARALLELISM VIA THE APIpython · anthropic SDK

You don't get Dynamic Workflows' auto-orchestration on the raw API, but you can fan out your own parallel calls and combine them — you stay in full control of how many run:

import asyncio, anthropic

client = anthropic.AsyncAnthropic()

async def agent(task):
    r = await client.messages.create(
        model="claude-opus-4-8",
        max_tokens=1500,
        output_config={"effort": "xhigh"},
        messages=[{"role": "user", "content": task}],
    )
    return r.content[0].text, r.usage.output_tokens

async def main(tasks):
    results = await asyncio.gather(*[agent(t) for t in tasks])
    # you know exactly how many agents ran — len(tasks) — and each usage
    return results

This is "tens of parallel calls you orchestrate." Dynamic Workflows is "Claude writes and runs that orchestration for you, at much larger scale, with verification." Different tools for different sizes of job.

// TAKEAWAYS

EFFORT IS THE LEVER

Most spend savings come from routing simple work to low effort (and cheaper models). Reserve xhigh/max for the genuinely hard tasks.

HONESTY COMPOUNDS

A model that flags its own uncertainty early saves you hours of debugging later. The longer the task, the more this matters.

MATCH MODEL TO JOB

Sonnet for daily work, Haiku for quick/simple, Opus for the hard, high-stakes problems. "Always Opus" is the costly default.

APPROVE BIG RUNS

Autonomous, long-horizon work can burn tokens fast. Cap output and confirm cost before launching — the way Claude Code does.
