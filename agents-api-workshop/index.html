OpenAI Agents API: Building a Research Agent

The Agents API gives your application access to the Codex harness through an OpenAI-managed API. OpenAI manages sessions, orchestration, context compaction, and recovery while your application provides tools and chooses its execution environment. This workshop teaches the core harness concepts through a single case study: a research agent that can search, retrieve, and synthesize information.

SessionDurable agent instance that persists state
TurnOne cycle of work within a session
ItemsSaved messages and tool calls
EventsLive progress streamed to your app

By the end you will understand how the managed Codex harness works: how to create sessions, follow events, wire tools, manage context as an attention budget, and resume or steer agents mid-task. The code samples are Python-first and presentation-friendly.

How to use this

Every module has one lab. The labs work in demo mode without an API key. The Connect panel on the right lets you use OpenRouter to run live calls if you want to experiment with real requests. Figures are labelled quoted when copied from OpenAI documentation, derived when computed on this page, and illustrative when simulated for teaching purposes.

ScopeThis workshop covers the core Agents API harness only: sessions, tools, events, compaction, resume/steer. Sandboxes (OpenAI-hosted and self-hosted execution environments) are an advanced topic for a future workshop. We mention them briefly where relevant.

02

Sessions

A session is a durable instance of an agent. It keeps the agent's configuration, conversation, and saved work over time. Reuse the same session to send follow-up messages and continue work.

# Create a session with an agent configuration
session = client.beta.agents.sessions.create(
    agent={
        "model": "gpt-6-astra",
        "instructions": "You are a research assistant...",
        "tools": [{"type": "web_search"}],
    },
    input="Research recent advances in battery technology.",
)

The session returns a session.id that you store. Use it to send follow-up messages, retrieve saved items, or inspect the session state. Sessions persist until you delete them.

03

Turns and events

A turn is one cycle of work within a session. When you send a message to an idle session, it starts a new turn. When you send a message during an active turn, it steers that turn. Turns run asynchronously; your application follows progress through streaming.

Turn started
agent.session.turn.started
Thinking
agent.session.item.created (reasoning)
Tool call
agent.session.item.created (tool_call)
Tool result
agent.session.item.created (tool_result)
Response
agent.session.item.created (message)
Turn completed
agent.session.turn.completed

Events report output and changes as the agent works. Key events to handle: turn.completed, turn.failed, turn.cancelled. Items are the saved messages and tool calls, including completed responses.

04

Tools

Tools extend what agents can do. The Agents API supports three categories: hosted tools (web_search, file_search), function calling (your code handles the call), and MCP servers (remote tool providers). A research agent typically uses web search for current information and may add file search for domain-specific documents.

tools = [
    {"type": "web_search"},
    {"type": "file_search", "vector_store_ids": ["vs_abc123"]},
    {
        "type": "mcp",
        "server_label": "company_docs",
        "transport": {
            "type": "http",
            "server_url": "https://docs.example.com/mcp"
        }
    },
    {
        "type": "function",
        "function": {
            "name": "save_finding",
            "description": "Save a research finding to the database",
            "parameters": {
                "type": "object",
                "properties": {
                    "title": {"type": "string"},
                    "summary": {"type": "string"},
                    "source_url": {"type": "string"}
                },
                "required": ["title", "summary"]
            }
        }
    }
]

05

Context compaction

The context window is an attention budget, not a trash bag. As a session grows, the Agents API automatically summarizes previous work to keep the context within limits. This is compaction: the harness creates a condensed representation of earlier turns so the agent can continue without losing track of what it learned.

How compaction works

The Codex harness monitors context usage. When the conversation approaches the model's context limit, it summarizes older turns into a compact form. The agent sees the summary plus recent turns, preserving continuity while fitting the budget.

You do not call compaction directly. The harness handles it. But understanding that it happens explains why long sessions remain coherent and why token usage does not grow linearly with conversation length.

06

Resume and steer

Sessions are durable. You can send another message to the same session to continue work. If the agent is idle, your message starts a new turn. If the agent is working, your message steers the active turn. This lets you correct course without starting over.

# Continue an existing session
client.beta.agents.sessions.events.create(
    session_id,
    events=[{
        "type": "agent.session.input.message",
        "input": [{
            "role": "user",
            "content": [{"type": "input_text", "text": "Focus on the European market."}]
        }]
    }]
)

To cancel an active turn, send a cancel event. The session and its previous work remain available.

# Cancel the current turn
client.beta.agents.sessions.events.create(
    session_id,
    events=[{"type": "agent.session.input.cancel"}]
)

Debrief

What you can now say

    Honest limitations

    This workshop covers the core Agents API harness. It does not cover sandboxes (OpenAI-hosted or self-hosted execution environments), which are how agents run code and edit files. Sandboxes add significant capability but also complexity; they are the subject of a future advanced workshop.

    The Agents API currently supports data residency only in the United States and does not support Zero Data Retention (ZDR). Session data persists until you delete it. Check the OpenAI data controls documentation for current policies.

    Anthropic note

    Claude and Anthropic have their own agent APIs with different design choices. A future workshop will cover building interchangeable harnesses that work across vendors. For now, the patterns here (sessions, tools, events, compaction) transfer conceptually even when the API shapes differ.
