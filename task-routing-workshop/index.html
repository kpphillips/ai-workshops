Task routing

A router chooses which model answers a request: RouteLLM trains that choice between a strong model and a weak model on human preference data, and FrugalGPT's cascade calls models in sequence and stops when a score says the generation is reliable enough. Halden Instruments, a fictional internal IT queue, is the running example; its tickets are text, and it is not a product.

Task classification

RouteLLM learns which of two models a preference label would pick, and Hybrid LLM trains a BERT-style encoder to score whether the small model's answer will be close enough to the large model's. Rule, classifier, and LLM routers

RouteLLM's BERT router and its causal-LLM router both turn a query into a win probability, and a threshold turns that probability into a strong or weak choice. The keyword router in the lab is a rule this page applies to the fictional tickets; that paper does not train this rule.

Quoted Router architectures in RouteLLM, section 4. The win probability is for the strong model against the weak model.
RouterWhat the paper specifies
Similarity-weighted rankingBradley-Terry coefficients solved at inference time. Each training query is weighted by embedding similarity to the new query.
Matrix factorizationA bilinear score from model and query embeddings, trained on the preference data.
BERT classifierBERT base embeds the query. A logistic regression head on the CLS token outputs the win probability. Full-parameter fine-tune.
Causal LLM classifierLlama 3 8B. An instruction prompt contains the query, and the win probability is a softmax over label tokens added to the vocabulary. No separate classification head.

Fallbacks and escalation

OpenRouter's models list tries the next model when the current one returns an error, including downtime, rate limits, context-length errors, and moderation flags. FrugalGPT's cascade is a separate step: it can move on after a successful generation when a score says that generation is not reliable enough.

Quoted What moves a request along, and what the source says about price. The Halden chain in the lab is not one of these products.
MechanismMove to the next model whenPrice note in the source
OpenRouter modelsThe current model returns an error. The docs list context length, moderation flags, rate limits, and downtime. Any error can trigger a fallback by default.The request is priced using the model that was ultimately used, returned in the response model field.
OpenRouter provider routingAnother provider of the same model. allow_fallbacks defaults to true.This stays on one model id. It is not the models list.
FrugalGPT cascadeThe generation score is below that step's threshold. The paper's reported study uses a cascade length of 3.Cost in their formulation adds the prompt, generation, and any per-request fee of each API that was queried.
Bedrock prompt routerThe guide's fallback model is an anchor. The router leaves it when the response-quality difference says another model in the family is far enough ahead. The API reference types responseQualityDifference as a double from 0 to 100.The user guide's example: a difference of 10% with Nova Lite as the fallback switches to Nova Pro only when Nova Pro's predicted quality is more than 10% higher.
