Zero trust for AI agents

Zero trust, in NIST SP 800-207 (August 2020), grants no implicit trust from network location or from who owns an asset. Authentication and authorization are separate steps before a session to a resource. A text-only receptionist for a home-services desk is the running example. It reads and writes messages. The desk, the messages, and the tool names are fictional, and they are not a product.

NIST does not use those three names. Section 2 says trust is never granted implicitly but must be continually evaluated. Its operative definition is a set of concepts for enforcing accurate, least-privilege, per-request access decisions in the face of a network viewed as compromised. The tenets apply inside an organization or with a partner, not to anonymous public or consumer-facing processes. The customer is an external actor. The controls below bind the agent's tools.

Derived Derived here: a customer message is not the agent. The agent is a subject. A tool is a resource. A shared key is a credential. Network location is not a reason to trust the request. This is not a figure from NIST SP 800-207.

Per-tool permissions

NIST's operative definition is a least-privilege decision on each request. Tenet 3 says access to one resource does not grant access to a different resource, and that the privileges should be the ones needed to complete the task. OWASP LLM06:2025 names three root causes of excessive agency: excessive functionality, excessive permissions, and excessive autonomy.

That is ASI03, Identity and Privilege Abuse. The four allows in the convention are a worked example for this fictional desk. They are not an OWASP requirement.

Untrusted input

OWASP LLM01:2025 defines prompt injection as a user prompt that alters the model's behavior or output in unintended ways. A direct injection is in the user's own prompt. An indirect injection is in external content the model accepts, such as a file, and that content alters behavior. The same entry says to separate and clearly mark untrusted content, and to keep the model's privileges at the minimum for the task.

ASI01, Agent Goal Hijack, in the agentic top 10 says to treat natural-language inputs, including retrieved content, as untrusted before they influence a goal or a tool. It distinguishes that multi-step effect from LLM01's focus on a single model response. NIST section 5.7 discusses a different setting, software agents used in zero trust administration, and says an attacker who can interact with such an agent could induce it to perform a task the attacker is not privileged to perform. Mapping that sentence onto this desk's messages is a derivation on this page, not a scenario in the NIST publication.

Scoped, short-lived credentials

NIST tenet 3 grants access per session, with the least privileges needed for that task, and says authorization for one resource does not extend to another. Tenet 6 says authentication and authorization are enforced before access, and that policy can require a fresh check on a timer or when a new resource is requested. Section 3 says the policy engine logs the decision as approved or denied, and the policy administrator generates the session-specific credential used to reach the resource.

    Audit log

    NIST section 3 says the policy engine makes and logs each decision as approved or denied. Tenet 7 says the enterprise collects information about asset state and communications and uses it to improve its security posture. LLM06:2025 says logging and monitoring will not prevent excessive agency. They can limit damage by making an unwanted action visible. ASI01 says permitted actions should be explicit enough to audit.

    A log line for this desk needs four fields: which identity ran, which tool it asked for, whether the policy allowed it, and which credential was used. The rows in the lab were written for this page.

      One honest limitationNIST SP 800-207 is an enterprise architecture publication from August 2020. Section 5.7 says how a software agent authenticates to zero trust components is an open issue, and that an attacker who can interact with the agent could induce a task the attacker is not privileged to perform.
